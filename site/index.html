银行 AI 智能体 · 产品原型

说话就能办业务，
每一步都有据可查。

转账、账单、理财、卡片与订阅，一句话交给 AI 管家。系统把自然语言拆成可执行的任务图，按五档权限决定自动执行、确认、复述、多因子验证或转人工；余额与回执只由工具结果渲染，全程写入哈希链审计。

Execution Chain

一句话，拆成一条
可审计的执行链。

大模型负责理解，不负责放行。意图、规划、授权、执行四层分工，任何一层都不单独决定资金动作。

01 / 理解

意图与槽位

LLM 输出结构化意图，规则引擎与 Zod 快照校验兜底；置信度不足时先澄清，不猜测收款人。

JSON 模式 · 8s 超时
02 / 规划

模板实例化为 DAG

18 个业务模板生成有向无环图，按拓扑序执行，支持暂停、重试、补偿与计划任务。

18 模板 · 拓扑执行
03 / 授权

风险打分与权限融合

风控智能体输出 0–100 分，与静态档位取较高者；确认摘要绑定参数，授权 90 秒内单次有效。

finalTier = max(静态, 风控)
04 / 交付

工具结果渲染

余额、流水、回执只读工具返回值；数字一致性守卫拦截证据外金额，条目写入哈希链。

事实锁定 · 可回放

Scenarios

六个场景，
共享同一套安全内核。

每个场景都有明确的工具边界与可逆语义。批量任务一次确认，每个节点仍独立签发授权。

智能转账

按姓名、手机号或备注转账；同名联系人先澄清，新收款人要求复述姓名，支持定时转账与 AA 收款。

“给林晚转 520 元，备注爱你”

账单分析

月 / 年账单、分类聚合、上期对比、异常交易与重复扣费；金额与分类全部来自流水工具。

“这个月花了多少？有异常消费吗”

理财操作

读取风险测评与产品匹配结果，展示持仓和收益；申购、赎回进入 T3 多因子验证。

“把活期里的 2 万申购稳健理财”

卡片管理

卡片与额度总览、虚拟卡申请、调额、冻结与解冻；挂失、解挂必须人脸加短信。

“卡片丢了，先挂失”

订阅代扣

识别自动续费、涨价与重复扣费，列明代扣方与周期，一键取消并保留恢复入口。

“把不用的订阅都取消”

生日联动

从一句“我爱人下周生日”拆出预算锁定、鲜花蛋糕预约与日程写入，一次确认批量执行。

“我爱人下周生日，帮我提前安排”

Five Tiers

五档权限，
按风险逐步加码。

静态档位由工具与金额决定，风控智能体再按 14 类信号打分。两档取高，只升不降；超过产品额度上限才拒绝。

T0

自动执行

Auto

余额、流水、账单分析、产品与持仓查询。只读且不动资金，确认意图后直接执行。

AUTO
T1

摘要确认

Summary

不超过 ¥1,000 的转账、订阅取消、小额调额等黄色操作。展示完整参数，一次确认。

摘要90s 单次授权
T2

收款人复述

Payee echo

在摘要之上手输收款人姓名，规范化后比对。防止改名联系人、注入话术与选错同名对象。

摘要姓名复述
T3

多因子验证

Step-up

人脸或本机生物识别；单笔超过 ¥5,000、挂失与解挂再加短信。挑战与操作摘要绑定。

摘要复述人脸短信
T4

人工审核

Review

单笔超过 ¥5 万进入审核队列，延迟 10 分钟到账，期内可撤销；拒绝或超时自动退回。

延迟到账可撤销人工复核
risk-agent-v1金额占比、行为基线、收款人新异性、深夜、频次、拆分规避、会话风险、注入嫌疑、低置信度、风险名单、诈骗话术、收款人替换、额度余量等 14 类信号加权。
finalTier = max(静态档, 风控档)分数段 35 / 60 / 85 映射到 T2 / T3 / T4。风控只读账本与会话事实，模型不参与打分。
一单一授权digest 覆盖用户、会话、节点、工具与规范化参数；执行前重算，改单返回 DIGEST_MISMATCH，重放返回 GRANT_ALREADY_USED。

拒绝边界：单笔超过 ¥200,000 或当日累计超过 ¥500,000 才硬阻断；5 万元以上进入人工审核，不再一刀切禁止。

事实锁定

LLM 只输出意图与槽位，余额与回执由工具结果模板渲染；数字守卫拦截证据外金额。

注入三层防御

输入规则、模型嫌疑信号、服务端工具白名单与策略彼此独立；连续命中触发熔断。

哈希链审计

append-only JSONL，逐条链接 userId、类型、摘要与载荷哈希；每 50 条写入 checkpoint。

并发额度台账

used = COMMITTED + HELD，预留 120 秒过期；用户锁串行化，避免并发双花。

熔断与接管

3 次工具失败或 2 次注入命中锁定 10 分钟；支持中断、接管、恢复、终止与逆序回退。

受限沙箱

worker + vm，无文件、网络与进程访问；800ms 软超时、2.2s 硬终止，静态检查越界调用。

Architecture

理解、安全、工具、客户端，

PRINCIPLE 01

模型只管理解

LLM 输出意图与槽位，不直接调用工具；规则引擎、置信度与 Zod 校验负责兜底。

PRINCIPLE 02

授权先于执行

资金动作先过策略、摘要、一次性授权；提示词无法绕过服务端工具白名单与额度台账。

PRINCIPLE 03

失败显式关闭

HTTP 银行接入失败直接报错，不回退合成数据；LLM 不可用时切换到规则引擎并标注来源。

PRINCIPLE 04

证据可回放

每次运行有 runId，审计条目按用户隔离；可按 run 重建意图、策略、授权与工具结果。

Known Limits

这是可运行的原型，
不是生产银行。

默认运行在合成数据与演示核验通道上；真实资金、正式客户与行方系统均未接入。以下边界来自开发期自查，提交评审时不作隐藏。

阅读完整风险清单（20 条） ↗
  1. 核验通道默认演示。人脸为页面动画或本机 WebAuthn，短信使用演示下发；配置 HTTP Provider 后才以合作方服务端结果为准。
  2. 状态为单机实现。多用户数据与额度台账存于 JSON 文件，重启丢失进行中会话；多实例需 Postgres / Redis 与分布式锁。
  3. 审计链无外部锚定。哈希链能发现内容篡改，文件仍可被整体删除；无 WORM、KMS 签名与集中日志。
  4. 行方联调尚未完成。已交付签名契约与联调桩，客户绑定、mTLS、异步对账与历史流水分页需生产环境补齐。
  5. 人工审核缺少职责分离。T4 入队前跳过摘要与多因子，批准后未回写额度台账；生产需双人复核与独立审核角色。
