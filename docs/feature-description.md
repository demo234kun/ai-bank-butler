# AI 银行管家 · 功能与设计说明

作品定位：用户说一句，Agent 把业务办完。**模型只负责理解意图，钱由策略引擎放行**——权限分级、一次性授权、决策审计、补偿回退构成 Agent 的执行骨架。行业对标 Revolut AIR，差异在于把"敢不敢让它操作账户"作为第一设计目标：可查询、可确认、可回退、可追责。

---

## 一、覆盖场景（赛题六大场景全覆盖）

**智能转账。** 按人名、手机号、备注发起；同名联系人先澄清再执行；支持定时转账（到点真实扣款）、拆分 AA 收款、当日冲正与额度累计。

**账单分析。** 消费分类统计、环比、异常交易识别、重复扣费检测、月度与年度账单报告。分类由流水推导，不依赖预设样例。

**理财操作。** 风险评估问卷 → 风险等级 → 适当性上限 → 产品推荐与对比 → 一键申购 / 赎回 → 持仓与浮动收益。推荐不等于申购，申购是红色操作。

**卡片管理。** 卡片与额度总览、虚拟卡申请与注销、额度调整、交易限制与解锁、挂失与解挂。

**订阅 / 代扣管理。** 自动识别订阅扣费与涨价，续费提醒，一键取消并可恢复。

**跨场景联动。** 从"我爱人下周生日"解析日期：当月锁定 1000 元活期预算，生日前 2 天订购鲜花、前 1 天订购蛋糕并写入日程。三个黄色操作合并成一张确认单，一次批准、分别授权、分别留痕；预算到期自动释放。

## 二、权限分级机制

| 级别 | 执行策略 | 本系统的判定 |
| --- | --- | --- |
| 绿色 | 自动执行 | 余额与账户查询、交易记录、账单分析、理财收益与持仓查询、订阅扫描。确认意图后直接执行，不二次确认 |
| 黄色 | 用户确认 | 小额转账（日累计 ≤ 1000 元）、订阅查询与取消、虚拟卡申请、额度调整、卡片冻结/解冻、生日联动的预算锁定与订购 |
| 红色 | 强验证 | 大额转账（日累计 > 1000 元）、卡片挂失与解挂、理财产品申购/赎回、单笔 > 5000 元升级为双因子 |

判定在服务端策略引擎完成，输入是**金额 + 当日已用额度 + 操作类型 + 会话风险状态**，与模型输出无关：模型说"这是小额"不改变分级。

**确认单是哈希锁定的参数摘要。** 摘要哈希绑定 用户 + 会话 + run + 节点 + 全部参数，展示收款人、金额、账户、备注与剩余额度。确认后签发一次性授权，90 秒过期、用后即废；期间参数被改、额度被占用导致风险升级，旧授权立即作废并重新要求验证。

**5 万元硬阻断**，任何授权都不能越过。

**多因子。** 红色操作可用本机生物识别（Windows Hello / Touch ID / Face ID，WebAuthn 平台认证器，签名由服务端校验 origin、rpId、一次性挑战与签名计数器）、签约活体人脸、或短信验证码；短信必须先由服务端下发再校验，客户端伪造 `faceDone` 在真实通道下无效。U 盾未接入。

**与赛题表的差异。** 赛题把"密码修改"列为红色操作。本系统的改密码走"原密码校验 + 服务端会话 + 其他设备全部下线"，尚未纳入 Agent 的红色操作目录，也不支持用对话改密码。

## 三、安全机制

**幻觉防护。** 模型只输出受 JSON Schema 约束的意图与槽位，不生成执行计划、不产出金额、不写回执文案。回执由工具结果模板渲染，数字守卫扫描输出中的金额与百分比并要求与账本返回值一致，不一致则整段拒绝下发。账户、余额、收益率一律来自账本。

**注入防御。** 三层：输入侧规则打分（越权指令、绕过话术、系统提示探测）；模型侧嫌疑度升级；服务端策略、授权与工具白名单兜底。即使语言层被骗过，工具目录里没有的路径也执行不了。攻防实验室可现场验证摘要篡改、令牌重放与策略独立性。

**操作审计。** 追加式哈希链，`userId` 参与哈希，逐条记录意图解析、策略判定、授权签发、节点执行、补偿与人工介入，每 50 条 checkpoint；支持按用户过滤、按 run 回放，篡改副本链会被检出。

**异常熔断。** 连续工具失败或连续注入命中即锁定会话，必须人工复核解锁，解锁动作本身入链。

**沙箱环境。** 模型生成的统计代码在 worker + vm 内运行，无文件与网络权限，先做静态检查再执行，带超时与内存上限；输入数据只来自当前用户的只读快照。

## 四、意图理解与任务规划

**模糊与省略。** 上下文栈保留最近引用，"再转 200""就那个""换成 1000"可解析；金额、收款人、产品缺失时先澄清，不默认填值，不执行资金操作。

**隐含意图。** "我爱人下周生日"未被显式要求转账或下单，系统识别为跨场景规划任务并给出可确认的方案。

**任务拆解为 DAG。** 每个意图对应一套预置任务图（解析 → 校验 → 执行 → 渲染），拓扑执行、节点状态实时可见、依赖显式声明。规划器不接受模型生成的执行图，工具白名单由意图决定，因此模型无法扩展自己的权限边界。

**执行可控。** 待确认操作可取消；执行中可中断；人工可接管后再交还；可逆操作按逆序补偿回退（转账冲正、解冻、订阅恢复），不可逆操作（申购、挂失）只标记转人工，不伪造"撤销成功"。

**断流与恢复。** 事件流带序号，暂停即断流，刷新页面或确认后按序号续传，会话状态可完整恢复。

## 五、产品形态与渠道

手机 PWA，可安装到主屏独立运行；注册、登录、访客三条路径，账号、会话、额度、审计、工单按用户完全隔离。

账号侧：注册短信验证（一次性随机码）、找回密码（一次性重置令牌）、可开关的登录二次验证、改密后其他设备下线、服务端会话与设备撤销列表。

交互侧：语音输入走浏览器原生识别实时上屏，不支持的浏览器录音后交给服务端转写；账单行可点开看交易详情并直接提交争议申诉工单；风险测评结果决定可购买的产品等级，年度有效，过期即拦截申购，风险等级禁止手填。

服务端调度器每 10 秒扫描到点任务：定时转账扣款、预算释放、订单送达、日程提醒，执行前重新校验硬限额与可用余额，结果写入提醒中心与审计链。

`/console` 是评委视角的同一份现场：意图解析、DAG 节点、策略判定、授权摘要、审计链、攻防实验室、模型成本与缓存命中。

IM 渠道尚未接入。对话接口与渠道无关，接入只需增加消息适配层，把 IM 的消息事件转成 `/api/chat` 调用并把事件卡片渲染回消息体。

## 六、接入设计

默认使用本地仿真核心，切换配置即接入真实系统，两种模式共用同一套工具、策略与审计代码。

银行核心网关抽象出快照读取与操作写入两类接口；HTTP 实现带 HMAC-SHA256 请求签名（方法 + 路径 + 时间戳 + nonce + 报文哈希）、写操作幂等键、超时重试与客户端熔断，上游返回结构经 Schema 校验后才落库。短信、人脸、语音转写各自有演示与签约两种通道。

失败即关闭：真实模式下同步失败直接返回不可用，绝不回退到仿真数据；接入配置不完整时服务启动即失败。对外契约（接口、字段、错误码、幂等语义）与联调桩齐备，行方按契约映射到自有核心即可。

---

## 七、边界

真实账户读写、短信与活体、语音转写都需要行方与供应商凭据，当前交付的是契约与可切换实现。风险测评是简化问卷，争议工单只到受理与状态回显，风控只覆盖金额阈值与频次限流，无 U 盾、无 KYC 与账号注销，存储为单机 JSON。这些属于生产化阶段要补的课。
