# 安全自评报告

> 版本：v0.3 · 更新日期：2026-11-02 · 作品：AI 银行管家
> 性质：开发期自查，供比赛评审参考，不构成合规、法律或审计结论。默认运行在合成数据与演示核验通道上；配置 `BANKING_MODE=http` / `SMS_MODE=http` / `FACE_MODE=http` / `ASR_MODE=http` 后，账户读写与核验改走签约服务，失败即关闭、不回退仿真数据。

## 1. 范围

本报告评估「AI 银行管家」产品化原型（多用户 PWA + /console 评委模式，可公网 HTTPS 访问）在以下方面的实现：

- 权限分级（绿色自动 / 黄色确认 / 红色强验证）
- 幻觉防护与事实一致性
- 提示词注入与越权防御
- 操作审计与决策链路留痕
- 异常熔断与人工接管
- 账号认证、会话归属与多用户数据隔离
- 受限代码沙箱
- PWA 与演示环境的数据/隐私处理

不在本次范围：行方正式准入与联调、支付清算、征信、KYC、真实活体检测的供应商选型、生产级基础设施与监管认证。本报告只评估接入层与安全控制的代码实现。

## 2. 威胁模型

### 2.1 资产

- 用户资金与账户余额、交易流水、卡片额度、理财持仓、订阅代扣。
- 操作授权（确认、强验证、grant）。
- 审计日志与决策链路。
- 用户隐私（姓名、手机号、卡号、联系人、地址）。
- LLM API Key 与系统配置。

### 2.2 角色

- 普通用户（多用户注册 / 访客体验，数据按 userId 隔离）。
- 恶意输入者（通过对话注入、伪造身份、诱导模型越权）。
- 本地攻击者（可访问演示机文件系统/浏览器）。
- 外部依赖（LLM 服务、网络）。

### 2.3 主要威胁与对应控制

| 威胁 | 控制 | 残余风险 |
| --- | --- | --- |
| LLM 编造余额/交易结果 | 事实锁定渲染 + 数字一致性守卫 | 文案可能不自然；数字已被约束 |
| 提示词注入绕过权限 | 输入规则 + 模型信号 + 服务端工具/策略/grant | 漏报新话术；服务端仍兜底 |
| 确认后改单（TOCTOU） | digest 绑定参数 + 执行前重算 | 本地进程被完全控制时无法防御 |
| 授权令牌重放 | 单次消费 + TTL + 风险等级校验 | 多进程部署需共享存储 |
| 并发双花额度 | 预留-提交台账 + 用户锁 | 多实例需数据库行锁 |
| 同名联系人转错人 | 歧义澄清 + 联系人尾号/银行展示 | 用户误选仍可能发生 |
| 伪造行长/管理员身份 | 身份声明不构成授权；服务端策略独立 | 真实系统需登录/角色系统 |
| 删除/篡改审计 | append-only + 哈希链 + checkpoint + 副本演练 | 本地文件可被整体删除（非隐蔽） |
| 沙箱逃逸 | worker + vm + 无 IO + 超时 + 静态检查 | vm 非生产安全边界 |
| PII 外泄给 LLM | 手机号/卡号在提示词与审计中脱敏；工具只按需返回 | 用户仍可能输入其他敏感信息 |
| LLM 不可用/限流 | 缓存 + 规则引擎 + 离线开关 | 规则覆盖有限 |
| 演示时钟导致 TTL 错误 | 业务时间与安全 TTL 分离（墙钟） | 生产应统一时间源 |
| 连续失败/注入轰炸 | 3 次失败或 2 次注入熔断 10 分钟 | 用户级演示；生产需全局风控 |
| 撞库 / 暴力登录 | scrypt 密码哈希 + IP/手机号限流 | 无登录 MFA / 验证码 / 泄露密码检查 |
| 跨用户越权（IDOR） | 会话、确认、回放全部校验 userId | 单进程内存会话；无集中鉴权服务 |
| CSRF | HttpOnly + SameSite=Lax + JSON 请求 | 未强制 Origin/CSRF token |
| 公网访客滥用 / LLM 成本 | 访客创建限流 + 全局 LLM 日预算 | 无聊天频控与滥用检测 |
| 伪造 / 篡改银行核心响应 | HMAC 签名、5 分钟时间窗、nonce 防重放、Zod 快照校验、失败不回退 | 密钥管理与行方网关仍依赖生产基础设施 |
| 重复提交造成双花 | 本地幂等缓存 + 写操作 `Idempotency-Key` + 重试复用同一 key | 银行侧必须实现幂等去重与对账 |
| 绕过人脸 / 短信 | HTTP 模式只认 Provider 结果；固定码仅 demo 下发 | 供应商 SDK、活体等级与模板报备需联调 |
| PWA 缓存泄露 | SW 不缓存 `/api/`，只缓存静态 shell | 共享设备浏览器缓存/登录态风险 |
| 人工接管被滥用 | 接管/解锁写审计；界面仅限控制台 | 无操作员 RBAC（生产需补） |

## 3. 权限分级实现

### 3.1 分级矩阵

| 级别 | 执行策略 | 典型操作 | 认证 |
| --- | --- | --- | --- |
| 绿色 | 自动 | 余额、流水、账单分析、异常检测、产品/收益/持仓查询、沙箱统计 | 无 |
| 黄色 | 展示详情 + 明确确认 | 小额转账（计入当日累计 ≤ 1000 元）、定时转账、AA 收款、订阅取消、虚拟卡申请、调额 ≤ 2000 元、锁定活期预算、礼品 ≤ 300 元 | 一次性 PolicyGrant（90s，单次） |
| 红色 | 用户确认 + 多因子 | 大额转账（当日累计 > 1000 元）、理财申购/赎回、挂失/解挂、调额 > 2000 元 | 人脸；单笔 > 5000 元加短信；挂失/解挂加短信 |
| 拒绝 | 硬阻断 | 单笔 > 20 万元、当日累计 > 50 万元、熔断锁定、策略拒绝 | — |

> 五档模型（T0–T4）见 `packages/shared/src/riskTiers.ts`。1000 元仍是黄红分界；5 万元以上不再一刀切禁止，而是进入 T4 人工审核队列（延迟到账、可撤销）；只有超过产品额度上限（单笔 20 万 / 日累计 50 万）才拒绝。
>
> 档位 = max(静态档, 风控智能体档)。风控智能体 `policy/riskAgent.ts` 只读账本与会话事实，输出 0–100 分、命中信号与建议档位，随 `POLICY_DECISION` 入链；T2 起要求手输收款人姓名（`PAYEE_ECHO`），T4 转人工审核（`MANUAL_REVIEW_QUEUED` / `_APPROVED` / `_REJECTED` / `_EXPIRED`）。

### 3.2 实现路径

- 风险判定：`apps/server/src/policy/engine.ts`
  - 输入：工具、参数、当日已用/预留、熔断状态。
  - 输出：`baseRisk / effectiveRisk / decision / reasons / limit / explanation`。
  - 理由码：`SMALL_TRANSFER`、`DAILY_LIMIT_EXCEEDED`、`HIGH_VALUE`、`RED_BASE`、`TIER_FUSED`、`PRODUCT_CEILING`、`DAILY_CEILING`、`RISK_*`、`BREAKER_LOCKED`、`REVERSIBLE_OP` 等。
  - 风控智能体：`policy/riskAgent.ts` 十四类信号加权，输出分数、档位与可解释命中项；只读账本，模型不参与打分。
- 授权：`apps/server/src/policy/grant.ts`
  - `digest = sha256(userId|sessionId|runId|nodeId|tool|canonical(args))`。
  - 用户确认后签发；执行前校验节点、摘要、TTL、是否已用、当前风险是否高于授权风险。
  - 消费原子化（单进程同步），重放返回 `GRANT_ALREADY_USED`。
- 强验证：`apps/server/src/policy/stepup.ts`
  - 人脸 +（>5000/挂失/解挂）短信；90s；3 次错误熔断；挑战与 digest 绑定。
  - `SMS_MODE=demo` 下发一次性随机码（5 分钟有效、校验成功即删除），演示模式下随响应回传给页面展示，输入框不再自动填入；固定万能码已移除，未经服务端发送时任何验证码都返回 `SMS_NOT_SENT`。
  - `FACE_MODE=demo` 且未录入通行密钥时使用页面动画，界面标注"未采集真实人脸"；录入 WebAuthn 后改为本机生物识别签名，由服务端校验公钥与签名计数器。
  - `FACE_MODE=http` / `SMS_MODE=http` 时调用签约 Provider：短信必须由服务端先发送再校验；人脸必须由服务端向合作方确认 `passed`，客户端传 `faceDone=true` 不再生效。
- 批量黄色确认：`apps/server/src/agent/executor.ts`
  - 生日联动一次确认 3 个操作；确认单摘要覆盖全部节点，每个节点仍独立签发 grant 并执行前重校验。
- 取消/超时：`apps/server/src/agent/control.ts`
  - 待确认与强验证均 90s 超时；取消/超时会标记节点 `SKIPPED`，不产生资金变动。

### 3.3 关键边界

- 确认后再改金额：执行前重算摘要 → `DIGEST_MISMATCH`。
- 确认期间额度被其他操作占用：当前风险升级 → 旧 grant `RISK_ESCALATED`，重新强验证。
- 红色转账在额度已用完后仍可执行，但必须强验证并继续占用累计。
- 单笔 > 5 万元：进入 T4 人工审核队列（延迟到账、可撤销），不再直接拒绝。
- 单笔 > 20 万元或当日累计 > 50 万元：策略 DENY 并写审计。

## 4. 核心安全机制

### 4.1 幻觉防护

- LLM 只输出意图/槽位；`planner` 只实例化模板；`render` 只读工具结果。
- 数字守卫扫描 `¥金额` 与百分比，必须命中证据集合；失败则回退通用文案，并记入 `GuardStats`。
- 交易流水号、持仓 ID、订阅 ID 作为证据返回；审计链可追溯。
- 控制台展示“校验数字 / 拦截 / 注入拦截 / 渲染次数”。

### 4.2 注入防御

- 规则库覆盖：指令覆盖、提示词窃取、审计删除、身份伪造、跳过验证、强制转账、角色扮演、工具标记注入、数据越权。
- 评分 ≥45 阻断；LLM 侧 `injectionSuspicion` ≥0.75 升级阻断；连续 2 次命中熔断。
- 服务端工具白名单、意图白名单、策略引擎、grant、额度台账独立于提示词。
- 攻击实验室提供端到端发送与服务端自检（摘要篡改、令牌重放、策略独立性）。

### 4.3 审计

- append-only JSONL；`hash = sha256(seq|prevHash|userId|type|ts|summary|payloadHash)`；查询按用户过滤，回放校验 run 归属。
- 单例串行写入；每 50 条 checkpoint（count+head）。
- 脱敏：手机号、卡号、token、密码等字段/文本模式；payload 大小限制。
- 覆盖：注册/登录/访客/登出、用户输入（脱敏）、NLU、注入拦截、规划、策略、确认、grant、强验证、工具成功/失败、额度预留、补偿、熔断、接管、回退、导出、重置。
- 提供整链校验、副本篡改演练、按 run 回放。
- 已知局限：单机文件、无 WORM、无外部锚定；本地攻击者可删除整个文件（会被计数/校验发现，但无法阻止）。

### 4.4 熔断与人工接管

- 连续 3 次工具失败或 2 次注入命中 → 用户级锁定 10 分钟。
- 锁定时：聊天不调 LLM，工具调用直接 DENY；控制台人工复核解锁。
- 执行中支持中断、接管、恢复、终止、逆序回退；所有状态迁移写审计。
- 回退只处理 `reversible` 的成功节点；不可逆节点转人工工单，避免“假回退”。

### 4.5 额度与幂等

- 预留-提交台账：`used = COMMITTED + HELD`，`remaining = 1000 - used`；预留 120s 过期。
- 并发：单进程用户锁串行化；生产需数据库行锁/分布式锁。
- 幂等键绑定 session/run/node/tool/args；成功结果持久化，重放返回原结果。
- 日切使用演示时区的日期字符串，不依赖定时器。

### 4.6 沙箱

- worker 线程 + vm 上下文；无 `require/fs/net/process`；vm 800ms、worker 2.2s 硬终止；结果大小限制。
- 静态拒绝 `require(` / `process.` / `import` 等；运行时错误回传审计。
- 定位：**演示级受限计算环境**，不是生产安全边界。

### 4.7 数据与隐私

- 多用户账号 + 独立合成银行数据；密码 scrypt 哈希；登录态为 HMAC 签名 HttpOnly Cookie（7 天、SameSite=Lax、HTTPS 下 Secure）；没有真实 KYC。
- 访客一键体验创建独立账号；产品端与评委控制台共享账号数据、使用不同会话 key。
- 公网通过 HTTPS 隧道暴露；生产需固定在受控域名并设置 `COOKIE_SECURE=1`。
- 提示词发送给 LLM 前对手机号/卡号做脱敏；联系人只发送姓名/关系/银行/尾号。
- 审计落盘前脱敏；LLM API Key 只在服务端环境变量，不进入前端或仓库。
- 运行时数据位于 `data/`（已 gitignore），可用 `npm run reset` 清除。

### 4.8 时间与演示稳定性

- 业务日期使用可注入时钟（默认 2026-10-30 10:00），保证“生日前 2 天”可演示。
- 安全 TTL（确认、强验证、grant、预留）使用真实墙钟，避免冻结时钟导致“一打开就过期”。
- LLM 三级兜底、缓存、离线开关；一键重置。

### 4.9 账号与会话隔离

- 每个请求通过签名 Cookie 解析 `authUser`，会话写入 `userId`；`/api/session/:id`、确认、强验证、中断、接管、回退、审计回放均校验归属，跨用户访问返回 404。
- 每个用户独立 `BankState`（账户、额度、幂等、熔断）与审计视图；审计条目记录 `userId` 并参与哈希。
- 密码 `scrypt` + 随机 salt + `timingSafeEqual`；登录/注册/访客有内存限流；生产应替换为网关/Redis 与验证码。
- 账号切换会清理浏览器 session key；前端按 user id 重新挂载 Agent，旧会话不会串到新账号。
- 已知边界：登录 Cookie 一旦被复制，在 7 天内仍有效；没有服务端会话撤销/设备管理。

## 6. 已知风险清单（19 条，按优先级）

### P0 · 上线前必须处理

1. **公网滥用防护不足**：认证接口有 IP 限流，NLU 有全局 LLM 日调用上限（默认 500，超限自动规则兜底）；缺聊天频控、验证码与滥用检测。需补网关限流、WAF、LLM 预算告警与账号风控。
2. **银行接入未完成行方联调**：已交付签名 HTTP 契约与联调桩，缺真实客户绑定、授权同意、mTLS 证书加载、异步对账回调与历史流水分页；`appSecret` 与 `bref → custId` 映射须由生产环境提供。
3. **核验通道默认演示**：`FACE_MODE=demo` 且未录入通行密钥时接受页面动画结果，界面已标注"未采集真实人脸"；另有 WebAuthn 本机生物识别（服务端验签）与 `FACE_MODE=http` 活体 Provider 两条真实路径。真实短信需行方模板报备与供应商准入。
4. **存储与运行态为单机**：JSON 文件 + 内存运行态，仅支持单实例；重启丢失进行中会话与内存态挑战/令牌，多实例会破坏额度、会话与审计一致性。需 Postgres/Redis 与分布式锁。
5. **审计链缺少外部锚定**：追加式哈希链可检测内容篡改，但文件可被整体删除或替换；无 WORM、无 KMS 签名、无时间戳锚定与集中日志。

### P1 · 生产化阶段处理

6. **账号体系为原型级**：已有注册短信、找回密码、可开关登录 MFA、服务端会话与设备撤销；缺 KYC 与证件核验、设备指纹、账号注销、安全通知；密码最低 6 位且无泄露密码库检查。
7. **手机号明文入库**：`store.json` 保留登录手机号；密码哈希与令牌不落明文，数据文件未加密。需字段级加密与访问审计。
8. **CSRF 依赖 SameSite=Lax**：未强制 Origin 校验或双提交 token。
9. **控制台缺少角色权限**：`/console` 对任何已登录用户开放，入口隐藏在「我的」；不暴露他人数据，但会暴露技术链路。需评委访问码或 RBAC / 独立部署。
10. **风控数据源有限**：`risk-agent-v1` 已覆盖金额占比、30 天行为基线、收款人新异性、深夜、频次、拆分规避、会话风险、注入嫌疑、置信度、风险名单、诈骗话术、收款人替换与额度余量；设备指纹、商户与地区风险、真实行方名单仍需接入。
11. **沙箱强度有限**：worker + vm 阻断文件与网络，无法覆盖全部逃逸与资源耗尽；生产需容器 / microVM + seccomp + cgroup + 网络隔离。
12. **PII 识别不完整**：提示词对手机号与卡号脱敏，自由文本仍可能包含证件号、地址等；审计落盘需更强的 PII 过滤。
13. **模型依赖外部服务**：业务语句发送给 DeepSeek，极端表达可能误判意图；已有澄清、置信度、规则与离线兜底，无法保证 100%。生产需私有化模型、评测集与灰度。
14. **对账窗口未闭合**：存在"核心成功、客户端确认失败"窗口；桩实现返回完整快照并支持幂等查询，真实网关需按接入文档完成对账与结果补偿。
15. **撤销能力受清算时点约束**：转账冲正、订单取消按可逆语义补偿；真实支付通道的撤销窗口由清算规则决定，不可假设全部可回退。

### P2 · 演示与交付相关

16. **演示时钟与真实时钟分离**：便于演示计划任务，与生产时间语义不同；生产统一可信时间源。
17. **公网演示依赖临时隧道**：Quick Tunnel 域名随进程变化，机器休眠即失效；正式提交需固定域名与持久托管。Service Worker 只缓存静态壳，不缓存 API。
18. **争议处理只到受理**：工单生成、状态回显与 180 天窗口校验在服务端完成，受理后的调查与赔付由银行侧流程承担。
19. **未做渗透测试与第三方安全评估**：本报告为开发期自查，不等于认证或审计结论。

## 7. 生产化建议（优先级）

1. 在现有短信验证 / 找回密码 / 登录 MFA / 设备撤销之上接入正式 IAM：KYC 与证件核验、设备指纹、操作签名与账号注销；确认/强验证令牌与可信设备绑定。
2. 对公网部署增加网关限流、WAF、验证码、全局 LLM 日预算与聊天频控；监控成本与异常登录。
3. 使用 Postgres/Redis 实现账号、额度台账、幂等、会话与分布式锁；审计接 WORM/SIEM；字段级加密。
4. 私有化/专有云 LLM，输入输出双向 PII 过滤与内容安全；建立意图/槽位/注入评测集与回归门禁。
5. 沙箱迁移到容器/microVM，限制 CPU/内存/网络/系统调用；代码签名与制品扫描。
6. 风控升级：频次、设备、地理位置、收款人名单、行为基线、人工复核队列。
7. 建立安全开发生命周期：威胁建模、代码审计、依赖扫描、渗透测试、应急演练。
8. 合规评估：生成式 AI 服务备案/评估、数据分类分级、个人信息影响评估、模型可解释性与留痕。

## 9. 结论

产品化原型已经实现手机号注册/登录/访客、多用户数据与会话隔离、可安装 PWA、五档权限与风控智能体、复述确认、人工审核队列、强验证、注入防御、幻觉防护、审计、熔断、沙箱、DAG 与中断/回退/接管，并用单元测试、离线冒烟、真实 LLM 端到端、公网 HTTPS 与浏览器实测验证。

它适合作为**比赛演示与产品验证**，不应直接用于真实资金场景。上线前必须补齐正式 IAM、真实 MFA、公网反滥用与 LLM 配额、生产沙箱、分布式状态、审计基础设施、数据加密、风控与合规评估。
